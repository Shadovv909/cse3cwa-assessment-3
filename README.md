Phoneme Studio is a frontend-only Next.js application for teachers to create, preview, and export phoneme-based Wordle and Word Search classroom activities. Generated activities download as complete standalone HTML files that can be opened directly in a normal web browser.

## Included pages

- **Home:** project introduction and links to both activity builders.
- **About:** purpose, Assessment 1 scope, architecture, accessibility, and planned future expansion.
- **Wordle:** configurable phoneme Wordle builder with a playable preview.
- **Word Search:** configurable phoneme Word Search builder using a small editable word list.
- **Settings:** persistent light/dark theme and comfortable/compact spacing preferences.

The supplied broad HCE corpus is stored in `src/data/`. It includes the supplied phoneme inventory and 90 example words grouped into three-, four-, and five-phoneme entries.

## Run the project on Windows

This project has already been created with `create-next-app`. **Do not run `npx create-next-app` again inside this folder.**

### Easiest method

After extracting the ZIP, double-click:

```text
RUN-WEBSITE-WINDOWS.bat
```

The launcher installs any missing local dependencies and starts the correct Next.js development server. Open the `Local` address printed in the window, normally:

```text
http://localhost:3000
```

Keep the terminal window open while testing or recording. Stop the server with `Ctrl+C`.

### Manual method

Open PowerShell in the folder that contains `package.json`, then run:

```powershell
node --version
npm --version
Remove-Item -Recurse -Force node_modules, .next -ErrorAction SilentlyContinue
npm ci --include=dev
npm run dev
```

Use Node.js **20.9 or newer**. The VS Code Live Server extension is not required and must not be used to run this Next.js application. Do not use `Go Live`, port `5500`, or a `file:///` address for the builder application.

The main builder must be opened through the Next.js development server at `http://localhost:3000`. Only the standalone HTML files generated by the Wordle and Word Search pages are intended to open directly as files.

## Diagnose missing-dependency errors

If ESLint reports that it cannot find `eslint-config-next/core-web-vitals`, the local development dependencies were not installed completely. Reinstall them with:

```powershell
Remove-Item -Recurse -Force node_modules, .next -ErrorAction SilentlyContinue
npm ci --include=dev
```

Then verify that the local packages exist:

```powershell
node -p "require('./node_modules/eslint/package.json').version"
node -p "require('./node_modules/eslint-config-next/package.json').version"
node -p "require('./node_modules/next/package.json').version"
```

For this submission, the expected key versions are ESLint `9.39.5`, `eslint-config-next` `16.2.10`, and Next.js `16.2.10`.

## Verify before submission

The easiest Windows method is to double-click:

```text
CHECK-PROJECT-WINDOWS.bat
```

Or run manually:

```powershell
npm run check
```

The `check` script runs ESLint, TypeScript checking, six unit tests, and a production build. It validates the project but does **not** start the website. After the checks pass, run `npm run dev` to demonstrate the interface.

To test the production build locally:

```powershell
npm run build
npm run start
```

Then open <http://localhost:3000> again.
